# Event Schema — Computer Vision → Rest of Team

This is the stable interface between the Computer Vision module and
everyone else (backend API, frontend dashboard, AI assistant). If this
shape changes, all three consumers need to know — treat changes to this
file as a breaking-change PR, not a quiet edit.

## Where it comes from

`computer_vision/src/events.py` produces two files per run:
- `computer_vision/outputs/events/events.json`
- `computer_vision/outputs/events/events.csv`

(Not yet committed to git — generated by running the pipeline. See
`computer_vision/README.md` / `data/annotations/detection_findings.md` for
current status and how to (re)generate them.)

## Record shape

```json
{
  "event_id": "EVT_V004_001",
  "video_id": "V004",
  "start_time": 0.73,
  "end_time": 3.47,
  "behaviour": "throwing",
  "risk_level": "HIGH",
  "confidence": 0.6,
  "evidence": "outputs/clips/EVT_V004_001.mp4",
  "reason": "High-speed product motion while detached from nearest person (2.73s)",
  "damage_status": "potential_damage_risk"
}
```

## Field reference

| Field | Type | Notes |
|---|---|---|
| `event_id` | string | `EVT_<video_id>_<3-digit sequence>`, unique within a video |
| `video_id` | string | Matches the `video_id` column in `computer_vision/data/annotations/ground_truth.csv` (e.g. `V001`-`V006` for the 6 sample clips) |
| `start_time` / `end_time` | float (seconds) | Relative to the start of the source video, NOT wall-clock time |
| `behaviour` | string enum | One of: `dropping`, `throwing`, `dragging`, `rough_handling`, `improper_stacking`, `unstable_stacking`, `outside_designated_area`, `strap_assisted_handling`, `stepping_on_carton`, `unsafe_loading_sequence` — see `computer_vision/config/behaviours.yaml` for the full taxonomy (only the first 4 have a working rule-based detector as of this writing) |
| `risk_level` | string enum | `LOW` \| `MEDIUM` \| `HIGH` \| `CRITICAL` — comes from `behaviours.yaml`, not computed per-event |
| `confidence` | float 0-1 | Model/rule confidence, NOT a probability of actual damage |
| `evidence` | string (relative path) | Path to an extracted incident clip. **Not yet implemented** — `clips.py` doesn't exist yet, so this path currently won't resolve to a real file. Treat as "reserved for future use" until noted otherwise |
| `reason` | string | Human-readable explanation, safe to show directly in a UI |
| `damage_status` | string enum | Always `"potential_damage_risk"` currently. **Never** `"confirmed_product_damage"` — the CV module cannot verify actual physical damage from video alone, only flag risky behaviour. Do not let the frontend/assistant present these events as confirmed damage. |

## Known accuracy caveat (read before building on top of this)

As of this writing, `events.json`/`events.csv` should be treated as
**schema examples, not accuracy-validated output**. The product-detection
layer feeding the behaviour engine has a documented failure mode (see
`computer_vision/data/annotations/detection_findings.md`, section on
"Attempt B") that causes false `throwing` events on non-throwing footage.
A fix (YOLO-World open-vocabulary detection) is built but pending
validation. **Don't wire up a demo against real event counts/timestamps
until this note is removed.**

## Consuming this in the backend / frontend / AI assistant

- **Backend** (`backend/app/`): currently empty. Suggested minimal contract:
  an endpoint like `GET /events?video_id=V004` that reads `events.json` and
  returns the array as-is (or filtered/paginated). Keep field names
  identical to this doc — don't rename in transit.
- **Frontend**: render `behaviour`, `risk_level`, `confidence`, `reason`
  directly. Use `risk_level` for color-coding (e.g. red=HIGH/CRITICAL,
  amber=MEDIUM, green=LOW). Always show `damage_status` as "potential risk"
  language, never "confirmed damage" language — this is a hard requirement
  from the challenge brief's responsible-AI section, not a suggestion.
- **AI assistant**: `reason` is written to be quoted directly in a
  conversational answer. `event_id` lets the assistant reference a specific
  incident if the person asks "tell me more about EVT_V004_001".
